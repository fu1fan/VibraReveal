# 正式 USB Bulk 图像通道验收 · 2026-10-31

本记录替代旧 NCM/TCP 作为正式图像通道的验收结论。SSH、文件上传和部署始终经 Wi-Fi `192.168.8.204`；图像走自定义 Bulk，USB NCM/ADB 仍可共存。

## 实现与构建身份

- 板端 FunctionFS + Linux AIO，默认 32 × 256 KiB 异步请求；相机 16 个 V4L2 buffer，独立采集线程与 32 帧环形缓冲。Mac libusb 使用 16 × 256 KiB 异步请求环，Swift 按序拼接并校验每帧。
- 实时固定原始尺寸，不再逐帧等待应用 ACK，不覆盖待发帧。环形缓冲溢出或采集序号缺口明确失败；离线连续填充请求以使用最大带宽。
- CNB [cnb-3v6-1k68n7ur5](https://cnb.cool/fu1fan/VibraReveal/-/build/logs/cnb-3v6-1k68n7ur5) 成功。应用 commit `f0c343beccf41e0c7abafb873caa37725db48900`，干净源码。
- ARM64 `vr-stream` SHA256：`24f278cbcdc430178174750ad13bb2ccb178fd2117418d8e5474f5bf0ba569b2`。首版构建 cnb-eip-1k68n2e10 与最终构建的发送器二进制相同；最终构建增加可追溯的服务脚本制品。
- OCI：`docker.cnb.cool/fu1fan/vibrareveal/image-transport@sha256:c3718643991e012e45fb9db7caed1772d6f7c8fd6e23de5d6d9e99d1b3a877d2`。
- 固定 SDK digest 为 `d2a21493198e25881cb03144bf4dd45b76e773e6cbbad1b62d6debbd4aa73cef`。未在 Mac 交叉编译板端程序。
- 本轮不需要再改内核；使用此前 CNB 编译部署的 Linux 5.10.209 / 系统 commit `bc78f9d2f4a9e48d69f8b1dff38a3dd905f374bb`，已具备 FunctionFS 及相机 FPS 修复。

OV9281 `/dev/video11`，1280×800，Y10 以 uint16 LE 存储，stride=2560，每帧 2,048,000 字节。传感器配置 120 fps、vertical_blanking=110，关闭 compact。

## 突发、失败和重连

- 等相机 FD 打开（即 START 握手完成）后再暂停 Mac 接收进程；不能从进程启动时间猜测枚举已完成。
- 暂停 100 ms：600 帧完整，序号 0–599，零缺口/丢弃，缓冲最高占用 6 帧。
- 暂停 800 ms：发送端报 `Capture ring overrun`，两端均非零退出，没有伪造成功 END。
- 随后重新连接：240 帧全尺寸接收成功，零缺口/丢弃。
- 服务 start/capture/stop/restart 连续两轮通过；强制终止子发送器后，daemon 自动建立新会话。停止服务期间接收器明确失败。
- `/etc/init.d/S91vrstream`、启动器和 daemon 已部署，服务最终保持运行，等待 Mac 的下一次握手。Mac 默认路由仍经 Wi-Fi en0 / 192.168.8.1。

## 离线最大吞吐与字节一致性

板端 tmpfs RAW 文件 2.4576 GB（1,200 帧），接收端逐帧 CRC 校验、丢弃 payload，不做磁盘输出。默认板端队列 32、Mac 队列 16，每请求 256 KiB。

| 轮次 | 接收吞吐 MB/s | 发送吞吐 MB/s | 完整帧数 |
|---|---:|---:|---:|
| 1 | 412.070 | 412.075 | 1,200 |
| 2 | 417.409 | 417.418 | 1,200 |
| 3 | 413.358 | 413.372 | 1,200 |

最高接收 **417.4 MB/s ≈ 3.34 Gbit/s**，约为此前纯 Bulk 419.37 MB/s 的 99.5%；这是本次条件下观测的应用图像吞吐，不是所有存储介质的保证值。所有帧连续、CRC 和 END 校验通过。该速度不受录制 FPS=120 的节奏限制。

另外将 150 帧、307.2 MB RAW + 测试索引经 Bulk 写入 `.vri`，同步文件后完成 ACK：接收约 397.3 MB/s。重新解析录像，payload SHA256 与板端完全一致：
`40739b93c384c3c5bf546571da545e24a08136f3d7fa7c0780e815a6fcdd6fd8`。
索引逐字节一致，序号 12000–12149；此处是显式测试索引，不声称它来自相机实际采集时间。再次用 `vr-receive --archive` 校验通过。

## 回归与范围

26 项 Swift 测试通过（21 后端 + 5 协议），包含 Bulk 标志下拒绝序号缺口、尺寸变化和 END 丢帧计数。跨语言 TCP 兼容回归通过：文件/索引一致、离线 Metal、非整数帧率、过载自适应、断连及损坏拒绝。

这证明当前设备、线材和主机下约 5 分钟全分辨率 120 fps 图像传输无丢帧；不等于 Metal 算法能每帧完成处理，也不保证主机任意长暂停。没有在本轮重新验收物理拔插、整机重启或全天稳定性。服务脚本已安装并运行，开机路径仍需单独冷启动验收。Homebrew libusb 使用本机版本；未验证更旧 macOS 的二进制分发兼容性。
