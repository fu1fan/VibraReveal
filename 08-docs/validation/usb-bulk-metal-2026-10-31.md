# USB Bulk → Metal 实机验收 · 2026-10-31

已将正式 USB Bulk 输入接入现有 Metal 实时处理路径，并增加逐帧遥测与可重复的硬件测量。结果：**全分辨率处理平均完成 120.40 fps，但当前最新帧队列仍丢弃 0.183% 的输入帧，不能称为端到端零丢帧。** USB 层保持完整接收。

## 条件和测量边界

- RK3588 / OV9281 → USB SuperSpeed 自定义 Bulk → Apple M5 / Swift / Metal。SSH、时钟探测和部署均走 Wi-Fi。
- 源 1280×800 Y10，stride=2560；配置 120 fps，时间戳实测约 120.622 fps。
- Metal 全帧、三层、alpha=10、3–12 Hz 因果滤波、`--adaptive false`。逐帧验证处理尺寸始终 1280×800。
- 主测试 36,000 帧，约 298.5 秒；包含启动阶段，不删去丢帧或耗时尖峰。
- 处理耗时包含输入上传、Metal 编码/执行/等待和 Float32 读回，不能把它解释为纯 GPU 执行时间。
- 端到端定义为 **V4L2 单调采集时间戳 → Mac 结果回调入口**。不包含屏幕扫描、曝光起点、编码/显示，也不把因果滤波的频率相关相位延迟算成执行耗时。
- 主测试完整计算并读回像素，但不序列化 stdout；另外以正常 Float32 输出到 `/dev/null` 做一轮 7,200 帧对照。

## 时钟校准

板端 `vr-clock-probe` 使用与 V4L2 时间戳同域的 CLOCK_MONOTONIC。Mac Python `time.monotonic()` 与 Swift `ProcessInfo.systemUptime` 做了本地往返核对，最小半 RTT 约 4.92 µs，时钟差落在该区间内。

通过持续 SSH 进程，在测试前后及每约 20 秒重复探测，取各组最小 RTT 样本，按主机时间分段线性插值偏移。长测期间两端偏移变化约 **9.98 ms**，不能只用开头一次校时。

长测校准半 RTT 中位数 **1.95 ms**、最大 **2.51 ms**；这是校准样本的不确定度，不是采样间非线性漂移的严格上界。因此跨设备端到端数值属于带此精度限制的估计，主机内部延迟则直接使用同一单调时钟。

## 5 分钟主测试

| 项目 | 结果 |
|---|---:|
| 源帧 / USB 接收帧 | 36,000 / 36,000 |
| USB 序号缺口 / 发送队列丢弃 | 0 / 0 |
| Metal 完成 / 处理失败 | 35,934 / 0 |
| Metal 待处理队列替换 | 66（0.1833%） |
| 实际完成速率（按输入采集时段） | 120.401 fps |
| 输出完成事件间的平均速率 | 120.430 fps |
| 前 120 个源帧内丢弃 / 后续丢弃 | 3 / 63 |
| 滤波历史重置次数 | 61（包含首次初始化） |
| 板端图像环形缓冲最高占用 | 4 / 32 帧 |

平均完成速率略高于 120，是因为源实际约 120.622 fps；不能用平均帧率掩盖缺帧。连续丢弃会合并为一次后续历史重置，故重置次数不等于丢帧数。

单位 ms，各阶段分位数独立统计，不能直接相加：

| 阶段 | P50 | P95 | P99 | 最大 |
|---|---:|---:|---:|---:|
| 采集时间戳 → 结果可用（估算） | 17.865 | 20.005 | 24.738 | 104.401 |
| 采集时间戳 → 主机收齐并校验（估算） | 14.530 | 15.534 | 18.208 | 86.860 |
| 主机收齐 → 结果可用 | 3.340 | 5.046 | 7.131 | 67.103 |
| 处理调用（上传/Metal/等待/读回） | 3.167 | 4.734 | 6.024 | 64.771 |
| 排队与调度余量¹ | 0.147 | 0.283 | 2.364 | 59.212 |

¹ 同一帧 `结果时间 - 收齐时间 - 处理耗时`，含提交、线程调度及计时边界的小量开销，不等同于 GPU 队列等待。

采集到收齐一段包括传感器/驱动交付、板端拷贝与 CRC、USB、Mac 组帧与 CRC，不能全部归因于 USB 线缆传输。

当前 `RealtimeMagnifier` 保持“一帧处理中 + 一帧最新待处理”的策略。实测有处理/调度尖峰和集中到达的帧，待处理帧因此被替换；USB 输入仍全帧完整。平均处理时间有余量，但它不足以证明每个 8.33 ms 帧周期都能完成。没有为了改善统计而开启缩放、降低源帧率或隐藏丢弃。

## 正常输出路径对照

7,200 帧、约 59.8 秒，正常生成并序列化 Float32 输出到 `/dev/null`：

- USB 完整 7,200 帧；Metal 完成 7,185 帧，替换 15 帧（0.2083%），失败 0，实际完成 120.370 fps。
- 采集 → 结果可用：P50 **17.753 ms**，P95 **19.887 ms**，P99 **24.265 ms**。
- 采集 → 输出写入完成：P50 **18.066 ms**，P95 **20.336 ms**，P99 **24.908 ms**，最大 **80.676 ms**。
- 输出 sink 开销：P50 0.262 ms，P95 0.598 ms；该轮校准最大半 RTT 1.94 ms。

两轮非同时运行，系统负载不同，不能将细小数值差异视为序列化会加速计算。`/dev/null` 不是实际显示器、视频编码器或磁盘写入。
