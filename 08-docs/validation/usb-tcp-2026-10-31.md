# USB 纯 TCP 基准 · 2026-10-31

iperf3 经已验证的 USB NCM 路由测试；每组预热 3 秒、计量 30 秒，以下为接收端平均有效吞吐。
Mac 3.22、板端 3.10.1；板端 Linux 5.10.209，物理 SuperSpeed，MTU 1500，NCM 块大小 16 KiB。
图像协议、应用层逐帧 ACK、CRC、算法与图像写盘均不参与。测试串行进行，SSH 管理仍走 Wi-Fi。

| 方向/参数 | Gbit/s | MB/s | TCP 重传 |
| --- | ---: | ---: | ---: |
| RK → Mac，单流，默认 128 KiB 写入块 | 2.377 | 297.1 | 1 |
| RK → Mac，4 流 | 2.780 | 347.5 | 0 |
| RK → Mac，单流，零拷贝 | 2.731 | 341.4 | 0 |
| RK → Mac，8 流，零拷贝 | 2.780 | 347.5 | 0 |
| Mac → RK，单流 | 3.141 | 392.6 | 8 |
| RK → Mac，单流，1 MiB 写入块 | 2.773 | 346.6 | 0 |

当前已测 RK → Mac 最高约 348 MB/s；单流增加写入块后同样达到约 347 MB/s。
这些是当前软件、默认系统配置下的 30 秒测试结果，不代表硬件绝对上限或长期最低保证。
USB 5 Gbit/s 的 8b/10b 编码先将可用数据率降至 4 Gbit/s（500 MB/s），之后仍有 USB/NCM/以太网/IP/TCP 开销。
编码依据：[Synopsys USB 3.1 Physical and Protocol Layer Changes](https://www.synopsys.com/articles/usb31-protocol-layer-changes.html)。

中断采样显示 dwc3 IRQ 138 位于 CPU6，八流时该核 system 约 89.4%；接口 RX/TX error 均为 0。
NCM 块较小、中断处理开销和两端驱动是后续分析方向，尚无 profiling 证据将全部差额归因于某一项。
Mac IORegistry 的 IOLinkSpeed=2.5 Gbit/s 是驱动报告值，实测超过该值，不能作为硬性限速依据。
本次没有修改内核、sysctl、中断亲和性或 CPU governor；测试服务随后停止。

复现板端：`iperf3 -s -B 192.168.77.1 -p 5201`。
复现 Mac 单流：`iperf3 -c 192.168.77.1 -B 192.168.77.2 -p 5201 -R -l 1M -t 30 -O 3 -J`。
