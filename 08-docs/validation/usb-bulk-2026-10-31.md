## 方法与边界

- 同一板卡、线缆和 Mac，USB SuperSpeed；现有 Linux 5.10.209，无需重编内核。
- 临时添加 vendor interface ff/56/01；现有 NCM/ADB 保留但不承载测量数据。Mac 使用接口 3、IN endpoint 0x84。
- RK 使用 FunctionFS + 原生 Linux AIO，固定请求 256 KiB、深度 32；Mac 使用 libusb 1.0.30/IOKit 异步读取。
- MaxPacketSize=1024、bMaxBurst=15；现有 NCM 的 bMaxBurst 同样为 15，因此这里没有增加该参数。
- 预分配固定模式缓冲，每轮预热 3 秒，统计接收完成回调的实际字节和单调时钟；不经过网络协议、不写盘、不做图像生成或 CRC。
- 首个接收缓冲模式校验通过；没有逐字节检查整个计量窗口。重复模式不能检验图像序号/顺序，0 传输错误也不表示 USB 底层没有重试。
- 未测试真实相机通过 Bulk 传输、120 FPS 完整保帧、应用层反馈、端到端延迟或突发延迟分位数。不要由此声称图像系统已迁移到 Bulk。
- 窗口边界包含在途请求的计量误差；60 秒结果比短测更适合作为持续吞吐参考。
- 这是异步队列、大请求和直接端点访问的组合收益，未将每个因素的贡献完全分离。
