# 系统架构概览

> 本文描述 VibraReveal 的目标架构。

## 1. 数据流

```text
          OV9281 global-shutter camera
             RAW10 · up to 120 FPS
                       │ MIPI CSI-2
                       ▼
     ┌──────────────────────────────────────┐
     │ RK3588 · Linux edge device           │
     │                                      │
IMU ─┤ V4L2 capture / frame timestamps      │
     │ Vulkan compute / motion pre-analysis │
     │ RKNN inference / ROI tracking        │
     │ buffering / transport / control      │
     └──────────────────┬───────────────────┘
                        │ USB 3 NCM / TCP (VRI1)
                        │ RAW frames + timestamps + metadata
                        ▼
     ┌──────────────────────────────────────┐
     │ MacBook · Apple Silicon              │
     │ Metal motion magnification           │
     │ spectral analysis / heatmaps / UI    │
     └──────────────────────────────────────┘
```

**基本约束：** 图像采集和传输为关键路径；GPU、NPU、深度估计与热点分析应异步执行。所有衍生结果必须关联原始帧编号及对应采样时间。预分析结果是可撤销的建议，不能取代原始图像。

## 2. 软件模块与计算职责

| 模块           | 平台                      | 职责                                      | 状态                          |
| -------------- | ------------------------- | ----------------------------------------- | ----------------------------- |
| 图像采集与缓冲 | RK3588 CPU / V4L2         | RAW10、帧序号、曝光与队列                 | 驱动基础已有；应用待集成      |
| 边缘运动分析   | RK3588 Mali-G610 / Vulkan | 峰值对焦、选区边缘、实时/离线相位放大 | 后端已实现；Tile 热点扫描与多任务并发待扩展 |
| 场景感知       | RK3588 NPU / RKNN         | MobileSAM 点/框物品选择与 ROI 掩膜 | 交互分割后端已实现；追踪/深度估计未实现 |
| IMU采集及对齐  | RK3588 / SPI              | 自振频谱、时间基准与同步                  | 规划中                        |
| 高速传输       | RK3588 ↔ MacBook          | VRI1 RAW 帧、时间戳、序号、CRC；USB NCM | 实时有界/自适应与离线连续传输；见验收记录 |
| 相位运动放大   | MacBook / Metal           | 时域滤波、金字塔、放大和重建              | 已有无界面实时/离线后端基线；待相机链路验收 |
| 测量与可视化   | MacBook                   | 频谱、时频图、热力图、选区操作            | 规划中                        |

分块预分析保留原始像素尺寸时，仍应保证对应Tile的**时间采样连续性**。逐帧轮流切换Tile虽然不会降低相机采集FPS，却会降低该Tile的有效时间采样率；需要采用连续特征采样或缓存连续原始帧后异步分析。

## 3. RK3588 计算后端

板端接口与构建命令见 [五项后端](../../03-apps/rk3588/BACKENDS.md)。

1. GPU 峰值对焦：原图梯度、峰值掩膜、清晰度分数。
2. NPU 物品选择：MobileSAM 点/框交互分割，缓存 embedding，原图坐标掩膜。
3. GPU 物品边缘：在物体掩膜内部和边界窄带筛选强边缘，返回两侧测量区域及法线。
4. GPU 实时放大：固定 ROI、显式整数分频；严格检查处理预算、连续采样和输出。
5. GPU 离线放大：VRI1 逐帧完整处理，保持原始空间/时间采样；默认前后向零相位整段滤波，可显式选择因果滤波；磁盘暂存，Double时间递推。

这些是独立后端库/CLI，不包含 UI、追踪或采集服务的多消费者调度。
预览和选物允许按需异步调用；连续测振不可沿用预览的丢旧帧策略。
掩膜限定选区，测量使用原始灰度，不能直接把分割轮廓当成精确位移。
实际调用端必须保留源帧身份，并在选区变动时重建时域处理实例。

## 4. macOS 后端模式

实现及调用方式见 [macOS 后端](../../03-apps/macos/README.md)。实时模式优先保留时间采样率，按处理耗时降低空间分辨率；异步队列最多保留一帧处理中、一帧待处理，替换待处理帧时明确计数，后续因序号间断重置滤波历史。离线模式通过磁盘暂存完整片段，默认前向—反向零相位滤波，再按序逐帧重建，保留原始或 ROI 分辨率及每一帧，不受实时性能预算限制；资源不足直接报错。可导出指定空间位置/金字塔层的局部相位幅度谱与 PSD，增益范围为 0～200。

两个模式使用原始采集时间与源 FPS，输出携带原始序号、时间、ROI、实际工作尺寸及滤波重置标记。后端不包括 GUI、相机驱动和视频容器编解码。`VibraRevealTransport` 负责 VRI1 接收及原始录像；CLI 支持 `--connect` 和 `--archive`，保留真实采集元数据。无头 RAW 输入仍使用合成时间。
