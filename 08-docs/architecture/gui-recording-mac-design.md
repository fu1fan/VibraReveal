# 振见主程序录制与双端测量设计

状态：2026-10-31 的早期产品设计，2026-11-01 归档并补充实现对照。以下正文保留当时规划，不作为当前程序的功能或资源预算说明。当前操作以 [TOUCH_APP.md](../../03-apps/rk3588/TOUCH_APP.md) 为准，实测以[板端验证](../validation/rk3588-touch-2026-11-01.md)为准。

## 与当前实现的差异

- 已实现 RK3588 Qt 5.15.10 触屏应用、NPU 点/框选物、可编辑 ROI、实时/区间离线放大、曝光/帧率、全幅 RAW 录制及电脑直通。Mac 已有接收与分析库/CLI，原生 GUI 尚未实现。
- 录制 DDR 上限为用户要求的 **4 GiB**，按实时可用内存扣除系统预留，不采用下文早期建议的 2 GiB 录制池。压缩工作区及在途帧计入预算，具体保护见实现文档。
- 本机 RAW 已采用 Bitshuffle + LZ4 fast8 全字节无损压缩，当前实测场景约 30 秒 eMMC 录制节省 66.23%；不是下文固定原始字节率的容量预测，也不是任意场景保证。
- 当前录像始终全幅保存；ROI 仅用于分析。局部裁剪录像、实验 ID/修订号、控制权租约、跨端选区同步、电脑远程文件管理与断点续传仍是规划。
- 原始 USB Bulk 为正式图像通道；当前未启用压缩传输。默认录像目录示例为根分区 `/root/vibrareveal/recordings`，容量须现场检查。
- 原板已完成构建、相机、NPU、触屏事件及短时录制验证；下文完整验收条件尚未全部达到。

## 原始设计正文

目标平台为 RK3588 Qt 5.15.10 触屏与原生 macOS 应用。两端围绕同一实验协作，统一准备、选区、试运行、录制、分析、结果流程。

## 设计依据

- 板端实机：Linux 5.10.209，Qt 5.15.10，Weston 13.0.1，1024×600 屏幕，8 GB 级 DDR。2026-10-31 读取 MemTotal=8,044,568 KiB，MemAvailable=7,428,576 KiB；这不是并发计算时的可用量保证。
- 大容量根文件系统约57 GiB，可用约53 GiB；/userdata 只有约483 MiB 可用。建议在大容量文件系统建立 /var/lib/vibrareveal/recordings，启动时验证实际挂载、可写性和可用容量。不得把 /tmp、/run 或 /dev/shm 当成 eMMC。
- 240 MB/s 为用户提供的 eMMC 写速估计，按十进制 MB/s 计算，不是已完成的持续写盘验收。
- 当前格式为有效 RAW10 存 uint16 LE，不能按每像素10 bit估算。VRI1 支持 stride、序号、时间和 CRC；现有协议没有实验控制、裁剪原点和断点续传。
- Apple HIG 的布局、交互、可访问性原则指导整体体验。板端不照搬桌面小控件；Mac 使用原生窗口、工具栏、侧栏、检查器、快捷键和系统文件面板。

## 一次实验与六个阶段

实验是顶层对象，具有唯一 experimentId；录制有 recordingId，处理有 jobId。设备与Mac显示相同名称、当前阶段、参数修订号和数据所在地。

| 阶段 | 板端职责 | Mac职责 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| 准备 | 相机预览、人工调焦、曝光、存储状态 | 大屏预览、命名实验、检查数据目的地 | 相机、空间、缓冲和路径就绪 |
| 选区 | 冻结参考帧，点/框选择，正负点修正 | 同一参考帧精细选物、ROI坐标调整 | ROI合法，参考帧及参数修订号一致 |
| 试运行 | 固定ROI的实时放大，预算反馈 | 按所选计算设备预览、对照 | 用户认可画面与频带；不冒充准确度标定 |
| 录制 | 唯一采集服务、DDR缓冲、eMMC写盘 | 共享控制、原始接收、显示和状态 | 停止后完成收尾及完整性验证 |
| 分析 | 可选本机离线任务 | 原始片段导入、离线放大、已支持的局部相位频谱 | 完整输入，合法频带，计算资源足够 |
| 结果 | 查看摘要、完成状态和导入状态 | 原图对照、频谱、实验备注和结果管理 | 数据、参数、来源均可追溯 |

流程是导航线索，不用六个强制弹窗。用户可返回准备/选区；改变会话相关参数使试运行结论失效。录制期间锁定采集、录制ROI、帧率和位深，查看/显示缩放可继续改变。分析结果保留各自参数版本，修改参数创建新任务，不覆盖旧结果。

物体掩膜、测量边缘带、算法矩形ROI、录制矩形ROI是四个不同概念。默认算法ROI与录制ROI链接；解除链接时仍要求算法ROI处于可用录像范围内。局部录像不能在事后恢复框外像素。全幅录像允许事后重选分析ROI。

物理位移、自动追踪、IMU同步以及未实现的测量能力不进入可用菜单。Mac已有局部相位频谱时明确标注信号类型和Hz；未标定不显示μm或位移准确度。试运行可跳过，但记录其未验收状态。

## 两种录制范围

全局录制在UI显示为“全幅”：保存全部原始像素、原始位深、所有源帧及时间。局部录制显示为“局部 ROI”：在写入录制缓冲前逐行裁剪固定矩形并紧密打包，保存ROI内全部源帧，不降采样、不保存叠加标记、不隐式改传感器模式。物体选择可辅助确定矩形，但不生成形状不规则的稀疏录像。

开始录制前冻结范围、位深、FPS和配置修订号。ROI更改要停止当前录像并新建录像；全幅录像的分析ROI允许改变，但处理任务独立重启。

| 示例模式 | 尺寸及采样率 | 原始像素输入率 |
| --- | --- | --- |
| 全幅 | 1280×800×2 byte×120 FPS | 245.76 MB/s |
| 局部 | 640×400×2 byte×120 FPS | 61.44 MB/s |
| 局部 | 256×256×2 byte×120 FPS | 15.72864 MB/s |

另计每帧80 byte VRI1头（120 FPS时0.0096 MB/s）、行对齐与存储开销。裁剪并不减少传感器采集带宽，只减少录制池、写盘和可选传输负载。无损10 bit打包可另行研究，但不是本版容量估算前提。

## DDR缓冲与强制停止

唯一采集服务 → 校验帧身份 → 全幅复制或ROI裁剪 → 预分配有界DDR队列 → 顺序写入eMMC。预览、USB和算法使用各自有界队列，不得长时间持有录制块而阻止回收。录制不得覆盖队列旧帧或通过丢帧释放空间。

8 GB板首版建议录制池上限2 GiB。启动前读取实际内存，扣除GUI、V4L2、GPU/NPU/驱动共享内存、传输、写盘在途内存及至少2 GiB系统余量；预算不足时缩小池或拒绝启动。提前分配并触碰内存；录制期间限制新建大内存任务，不靠swap承载录像。MemAvailable持续监测，低于配置保底值也触发停止。GPU/CMA等预算需要并发实测，不能只按MemAvailable计算。

录制池包含排队及未完成写入块。建议初始停止余量为 max(256 MiB, 停止响应上界×最大输入率+在途完整帧字节数)。保留区不是正常容量；容量应大于保留区及最小工作块。停止上界需实机测量，256 MiB只是初始设计值。

- 低于70%：正常显示缓冲用量。
- 达到70%：显示“写入落后，缓冲正在增加”及按最近趋势计算的剩余时间；不改变图像质量。
- 达到有效停止阈值 B-H、无法预留下一整帧、系统内存低于保底值，任一成立立即锁定截止帧并停止向本录像接收新帧。检查在采集/队列线程执行，不等待UI刷新。
- 正常停止和缓冲保护停止都先截断新数据，再排空已接受的完整帧，写END/元数据，执行持久化同步并以不覆盖方式发布。UI明确区分“录制已停止”和“保存完成”。不kill写盘进程，不等到OOM。
- 系统内存不足后释放不必要预览/分析资源，不把待保存数据丢弃。写盘故障或长期阻塞进入“保存失败/等待存储恢复”，保留可恢复部分，绝不无限接收新帧。
- 截止前发生CRC、采集序号缺口或写盘失败，录像标记不完整；主动在整帧边界提前结束且完整收尾，可标记“完整片段，因缓冲保护提前结束”。不将其伪装成达到计划时长。
- 本地录制停止只停止该录像订阅。其他实时采集消费者是否继续由其独立预算决定；一旦整体内存紧急，按优先级停止非必要消费者。

估算剩余缓冲时间：T=(B-H-Q)/(Rin-Rout)，仅在Rin>Rout时使用。Rout取真实写入完成的保守滚动值，不取进入页缓存的write速度；稳定时显示“当前未积压”，不显示无限录制保证。剩余可录时长取缓冲、磁盘容量和用户时长上限的最小值。

例：2 GiB池，256 MiB收尾余量，空队列，245.76 MB/s输入、240 MB/s稳定输出，理论缓冲停止约326秒（未计记录头/额外开销）；若输出降至200 MB/s，仅约41秒。53 GiB剩余空间再保留4 GiB系统空间，全幅容量约214秒。因此本机此配置可能先达到磁盘阈值。

顺序大块写入，目标块大小4–16 MiB。优先评估满足文件系统/块设备对齐约束的直接I/O；VRI1字节流跨块拼接，尾块单独处理，不在帧中插入对齐填充。若采用buffered I/O，需要明确限制在途和dirty数据，把页缓存计入预算，定期同步并统计完成延迟。最终fsync仍决定“保存完成”；DDR不是掉电保护。

磁盘停止条件必须预留尚未落盘的所有已接收字节、在途字节、结尾/索引及系统保留空间。磁盘空间在持续录像时被其他进程占用也必须被检测。存储容量与DDR阈值独立执行；/userdata不能作为本机默认高速录像目录。

## Mac联动与控制权

板端会话服务是采集与录制状态的唯一权威。QML和Mac都是客户端，不直接争抢V4L2、不各自启动第二个采集进程。默认新实验由发起端控制；另一端显示“Mac控制中”或“设备控制中”，用户显式接管。停止录制对两端始终可用；失联不转移控制给未知客户端。

每个命令携带 requestId、experimentId、预期配置revision和控制权epoch；同一requestId重试只执行一次。应用参数后服务返回实际配置及新revision，两端依据确认状态刷新，不把本地草稿当成生效值。忙碌期间禁止接管修改，允许停止。非录制阶段支持选区撤销；不能撤销已落盘采集历史。

| 保存位置 | 数据路径 | Mac慢或断线时 |
| --- | --- | --- |
| 设备（默认） | 相机→DDR→eMMC；Mac按需预览 | 本地继续；Mac预览可跳帧，不阻塞录制 |
| Mac | 相机→独立传输缓冲→USB Bulk→Mac磁盘 | 缓冲到阈值停止该录像；不静默切换eMMC |
| 双端副本（后续验收开放） | 独立本地写盘与可靠USB消费者 | 缺失副本明确降为单副本并记录；不能影响本地完成，不能称“双端完成” |

录制范围与保存位置是两个正交选项。首版开放“设备”和“Mac”，双端副本需并发验收后开放。Mac直录需要Mac存储和接收队列预算；板端DDR保护仍有效，但不存在本地eMMC备份承诺。

USB Bulk承载完整图像与离线文件；控制采用独立版本化通道，可先使用已配对认证的Wi-Fi连接，后续加入USB控制端点。区分“控制已连接”“图像已连接”“录像已保存”，不合并成一个连接绿点。现有VRSTART1/VRDONE01握手不具备上述控制能力，不复用VRI1保留字段。

初次配对在设备确认短码，保存设备身份；控制通道须认证。Mac通过能力协商获取后端、模型、输入格式、可用帧率、ROI限制、存储与协议版本。两端来源一致的会话快照用于重连恢复；过期命令、旧epoch、旧referenceFrame和旧revision明确拒绝。

冻结选区时共享同一源frameId及图像。Mac可发送框和正负点给板端NPU处理，也可编辑矩形ROI。保存原图坐标与裁剪原点，在板端/预览缩放/Mac回放间一致转换。能力不匹配时禁用对应操作并说明，不用旧参考帧掩膜冒充跟踪结果。

默认联机流程：板端取景调焦 → Mac接续同一实验并精细选区 → 选择计算位置进行试运行 → 任一授权端开始录制 → 两端显示同一截止及保存状态 → 本地保存完成后Mac一键导入 → Mac离线分析 → 两端同步结果摘要。Mac数据未导入时显示“在设备上”，不可仅因元数据同步就显示“已在Mac保存”。

传输与导入功能须新增：recordingId、分块偏移、校验、已确认块、最终文件哈希/大小及原子发布。中断后从确认的完整块恢复，不声称现有VRI1支持实时半帧续传。导入成功前不删除源文件；默认不自动删除源录像。录制期间暂停后台历史导入以避免eMMC读写竞争，用户主动继续时明确减少性能余量。

控制失联但图像正常：既定录像继续，Mac不得假定新参数已应用；板端本地停止有效。图像失联但控制正常：设备录制继续，Mac标记预览中断；Mac直录停止并保留不完整文件。重连后查询当前会话快照与完成状态，不自动重发Start。

## 界面与Apple HIG的对应

- 以实验内容为中心。板端顶栏保留实验名、控制归属和连接入口；主图占最大面积，右侧检查器只显示当前步骤所需参数。底部固定录制范围、主录制按钮和缓冲状态，不在多个页面重复不同版本的录制按钮。
- Mac采用实验侧栏、中央图像/回放、右侧检查器、下方时间轴。统一语义和流程，不强求与触屏像素级相同。支持菜单、键盘操作、拖放导入及ROI撤销；录制快捷键在文本输入时不触发。
- 工作流采用“准备、选区、试运行、录制、分析、结果”的轻量进度导航；主操作随阶段变化。高风险配置变更可用单个sheet，普通状态采用内联反馈，频繁同步不弹确认框。
- 主色使用明确蓝色；背景不透明、留白充足、分隔线清晰。正常文字对比目标≥4.5:1，重要主文本目标≥7:1，必要控件边界及图形目标≥3:1。避免低对比灰字、玻璃模糊和大量装饰卡片。UI可随系统明暗变化，但相机图像不做“主题增强”。
- 板端正文18px、辅助信息至少14px、触控目标至少48×48px。Mac使用平台文本样式。颜色不单独编码状态：录制配红点与文字，保护停止配原因，连接配设备名称。
- 录制期间默认只显示时长、全幅/局部、保存位置、DDR用量与停止按钮。输入/写入速度、阈值和估算误差放入可展开详情。70%预警才突出缓冲，保护停录时显示“缓冲余量不足，已停止采集此录像；正在保存剩余数据”。
- 停止按钮文案变为“正在保存…”，禁止新录制直到资源释放。保存完成显示实际时长、完整性、提前结束原因，以及“在Mac分析”。写盘失败不能显示成功勾。

## 格式与服务新增项

保留VRI1像素流兼容性，以版本化实验清单记录裁剪originX/originY、源尺寸、录制ROI、有效位深、源FPS、停止原因、首尾序号/时间、完整性、设备与算法版本。清单与像素流按事务方式发布；没有裁剪原点的局部录像不得被当成原图坐标数据。

局部录像可在width/height/stride表达裁剪后尺寸、sourceWidth/sourceHeight表达源尺寸，但原点不在VRI1内；通用旧播放器只能回放裁剪图。新客户端必须先完成清单/能力协商再开展跨端ROI编辑。

新增模块：CaptureSession、RecordingWriter、MemoryBudget、StorageBudget、ExperimentStore、ControlService、TransferManager，以及Mac对应客户端。采集/写盘/控制/GUI线程隔离；控制通道拥塞不延迟本地保护停止。

## 验收条件

1. 全幅与多个ROI逐像素核对，保留位深、序号与时间；跨端坐标与冻结帧一致。
2. 实测目标目录长时持续写入、fsync延迟、停写恢复和空间耗尽，不以缓存测速替代eMMC。
3. 注入240/200/0 MB/s写入情景，观察DDR有界、停止早于容量耗尽、无覆盖旧帧、收尾数据可验证；同时施加外部内存压力。
4. 实测采集停止响应上界及在途帧数量，修订H；验证系统低内存、设备断开、进程退出和写盘错误。
5. 双端同时Start、重复Stop、旧revision、控制接管、控制/图像分别断线、重连均只产生一个权威会话。
6. 本地录像不被Mac慢预览阻塞；Mac直录接收缓冲满后按同样规则停止。独立验证Mac原始录像与实时分析跳帧状态。
7. 真实1024×600触摸验证手指框选、数字输入、停止按钮、明暗环境可读性；Mac原生窗口验证快捷键、缩放和辅助功能。
